## ЧАСТЬ 2 — План доработки по направлениям

### 1. Каркас и адаптив админки (корень — нет admin/layout.tsx)
- **P0** Админка тянет шапку/мегаменю/нижнюю панель витрины; сетка не сворачивается, контент сжат в ~80px на телефоне → добавить `app/admin/layout.tsx` (свой минимальный каркас, без SiteHeader/Footer/ScreenBar) + сетку в CSS-классы с брейкпоинтом (сайдбар → верхнее меню/drawer на мобиле). **M.** [B0-1/2, B1-1/2/8]
- **P1** Широкие таблицы `overflow-hidden min-w-[760px]` обрезают правые колонки (вкл. «Редактировать») на мобиле → `overflow-x-auto`. **S.** [B1-4/5]
- **P1** Нет активного пункта меню; logout бледный → классы + `aria-current`. **S.**
- **P2** Раскол стиля (glass-витрина vs плоский Tailwind-админ), разнобой кнопок/инпутов, `opacity-70` у обработанных лидов (плохо видно) → мини-кит компонентов админки. **M.**

### 2. Фидбэк действий и error-boundaries
- **P0** Любая ошибка действия/детального роута = белый «Application error» → добавить `app/error.tsx` + `app/admin/error.tsx` + по роутам `catalog/product/podborki/order-success`; действия перевести на `{ok,error}`. **M.** [F-P0-3, A-P0-2/3/4]
- **P1** Нет подтверждения «Сохранено» нигде, кроме логина («тишина») → возвращать результат + показывать тост. **M.**
- **P1** `saveSettingsAction` — 5 upsert через `Promise.all` без транзакции (риск частичной записи цен-конфига) → `$transaction`. **S.**
- **P1** `updateProductAction` падает на нечисловой ручной цене, нет границ → zod-валидация/кламп. **S.**
- **P1** Списки без пагинации/поиска/фильтра; лиды `take:300`; «оборот» считается по последним 100 заказам (врёт) → пагинация + `aggregate`. **M–L.**
- **P1** Нигде нет удаления (лиды/заявки копятся) → архив/удаление с подтверждением. **M.**
- **P2** Нет подтверждений на approve/cancel/hide; sync синхронный (таймаут 180с, без прогресса) → confirm-диалоги + фоновая задача. **M–L.**

### 3. Безопасность / auth
- **P0** Подделываемые токены (фолбэк секрета) + ключ = пароль → требовать `ADMIN_SESSION_SECRET`, убрать фолбэки. **S.**
- **P0** Пароль админки в открытом виде → хранить хэш (bcrypt/argon2), constant-time. **S–M.**
- **P1** `/admin/*` не закрыт на уровне middleware (только `/account`) → добавить в matcher. **S.**
- **P1** Magic-link без rate-limit, создаёт User на каждый введённый email → троттлинг + перенос создания на verify. **M.**
- **P1** Нет rate-limit на вход в админку → троттлинг. **S.**
- **P1** `/order-success/[id]` отдаёт ФИО/телефон/состав по сырому id без проверки → подпись/привязка к сессии. **M.**
- **P2** Нет security-заголовков (HSTS/CSP/X-Frame-Options); GET `/logout` (CSRF); токен без отзыва; нет UI смены кредов/восстановления. **M.**

### 4. Ролевые цены и целостность заказа (бизнес-критично)
- **P0** GOV оформляет по рознице → решить политику: блокировать gov на `/cart` и `/checkout` (только КП) ИЛИ протащить роль в quote и принудительно «Цена по запросу». Рекомендуется блок. **M.**
- **P0** B2B берётся розница, хотя показана опт-цена → протащить роль в `buildOrderQuote`/`getProductsForQuote`, считать опт на сервере (не доверять клиенту). **M.**
- **P1** `b2bMinQuantity` не enforced → проверять в quote. **S.**
- **P1** Заказ без роли/тарифа/User; Telegram без роли → добавить `role`/`userId` в Order + в уведомление и в детали. **M.**
- **P1** Float-деньги → считать в Decimal/копейках. **M.**
- **P1** Мерцание роли у анонима (SSR cookie vs client localStorage в setTimeout) → cookie как единственный источник для первого рендера. **M.**
- **P2** `parsePercent` молча падает на 25% при мусоре в env; авторизованный b2c не может посмотреть опт-цены. **S.**

### 5. Витрина (UX)
- **P1** Один битый SKU ломает всю корзину, нет удаления строки → возвращать по-строчный статус, не throw. **M.**
- **P1** Холодный старт `/search` для кириллицы ~75с → скелетон/таймаут-сообщение + прогрев топ-запросов. **M–L.**
- **P1** Футер-рассылка `action="#"` мёртвая → подключить или убрать. **S.**
- **P1** Избранное не сохраняет порядок добавления → пересортировать по `skus`. **S.**
- **P1** «Быстрый заказ» очищает ВСЮ корзину → чистить только заказанный SKU. **S.**
- **P2** Скелетон `/catalog` в Tailwind-стиле (не glass); промо «В корзину» ничего не кладёт; статичное «8500 моделей»; нет навигации стрелками в саджесте. **M.**

### 6. Runtime / данные
- **P1** Полу-мигрированный кэш: `revalidate=300` ещё на catalog/[slug]/product; `podborki/[slug]` имеет и `revalidate`, и `force-dynamic` → выбрать одну стратегию. **S–M.**
- **P1** Счётчики фасетов спек-фильтра — по одному `count` на опцию последовательно → batch через `groupBy`. **M.**
- **P1** `page`/`price` без верхней границы → кламп. **S.**
- **P2** Homepage `force-dynamic` зависит от прогревщика; `quantity` без max; `decimalToNumber(null)=0` / `formatRub(null)="0 ₽"` — грабли; robots блокирует 2-ю страницу пагинации. **M.**

### 7. SEO / целостность
- **P1** Product JSON-LD отдаёт `"image":[]` у товаров без фото; sitemap включает товары без фото → убирать пустые массивы в `compactJsonLd` + фильтр в sitemap. **S.**
- **P2** Фолбэк-обрезка Telegram может разрезать тег у одной >2КБ строки. **S.**

## ТОП-5 фиксов с наибольшим рычагом
1. **`app/admin/layout.tsx` + адаптивный CSS-каркас** — снимает разом B0-1/2, B1-1/2/8, разблокирует весь этап. (M)
2. **Ролевой money-path** — блок gov на checkout + опт b2b считать на сервере. Единственные настоящие P0 по деньгам. (M)
3. **Error-boundaries + `{ok,error}` в действиях админки** — убирает белые экраны и «тишину» при сохранении. (M)
4. **Тройка безопасности**: обязательный `ADMIN_SESSION_SECRET`, хэш пароля, `/admin/*` в middleware. (S–M)
5. **Guard + транзакция в `rejectRoleUpgradeAction`**. (S)

## Что проверено и ХОРОШО (не «чинить»)
Цены пересчитываются на сервере (клиент не шлёт цены); 0₽ заблокирован от заказа; экранирование JSON-LD и Telegram; лиды пишутся в БД до Telegram; уведомления best-effort (не роняют заказ); approve-флоу с транзакцией и guard; magic-link (32 байта, single-use, 15 мин); whitelist ролей b2c|b2b|gov; защита open-redirect; `timingSafeEqual` на подпись токена.
