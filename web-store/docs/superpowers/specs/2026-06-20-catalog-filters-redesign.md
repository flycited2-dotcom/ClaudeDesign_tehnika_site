# ТЗ: Переработка системы фильтрации каталога climat-simf.ru

- **Дата:** 2026-06-20
- **Статус:** на ревью владельца (реализация НЕ начата)
- **Охват (согласовано):** топ-категории техники (профильные семейства) — образцово, затем тиражирование. Работа с данными — **улучшение логики/дизайна + расширение парсера атрибутов из названий** (не полная миграция схемы).
- **Платформы:** desktop-сайдбар (`.cat-layout` 280px) И мобильный шит (`mobile-filter-sheet`) — обе.

---

## 1. Цель и критерии успеха

**Цель:** сделать фильтрацию каталога функционально надёжной, логичной с точки зрения покупателя/маркетинга и аккуратной визуально — чтобы по любой профильной категории техники можно было быстро и без раздражения подобрать товар.

**Критерии успеха (проверяемые):**
1. **Дизайн:** ни один фильтр/значение/счётчик не обрезается и не вылезает за пределы колонки — ни на desktop (280px), ни на мобиле (360px). Длинные значения переносятся или усекаются осознанно (2 строки + полный текст доступен), а не «рубятся» `ellipsis` на полуслове.
2. **Релевантность:** в профильной категории показываются ТОЛЬКО параметры, осмысленные для неё (холодильник → объём/No Frost/класс/размеры; стиралка → загрузка/отжим/узкая; ТВ → диагональ/разрешение/Smart). Никаких чужих/мусорных параметров (smart_tv у посудомойки и т.п.).
3. **Без дублей:** покупатель не видит один и тот же критерий дважды («No Frost» в двух разных секциях). Единая понятная иерархия фильтров.
4. **Подбор работает:** применение/сброс/счётчики/URL-состояние/комбинации фильтров дают корректную выдачу; пустых выдач из-за «мёртвых» фасетов нет (фасет с 0 товаров не показывается).
5. **Данные богаче:** в топ-категориях у заметно большей доли товаров появляются структурные атрибуты (за счёт расширенного парсера) → фильтры наполняются, а не пустуют.
6. **Регрессий нет:** lint чисто, тесты зелёные (текущая база 194 + новые), build зелёный, прод-смоук 200.

## 2. Как устроена фильтрация сейчас (карта системы)

Каталог: ~54 326 товаров. Страница категории/поиска рендерит `catalog-view.tsx`, фильтры — `catalog-filters-panel.tsx` (desktop `FiltersPanel` в `<form action={basePath}>` + кнопка «Применить»; mobile — `mobile-filter-sheet.tsx` со своим sticky-футером). Применение фильтров — нативная GET-форма (URL-параметры), сервер строит Prisma-where и фасеты.

**Шесть групп фильтров (`catalog-filters-panel.tsx`):**
| Группа | Параметр URL | Источник | Механизм |
|---|---|---|---|
| Бренд | `brand` | фасет брендов (`catalog-brand-filters.ts`) | чекбоксы + поиск (`SearchableCheckboxList`) |
| Цена, ₽ | `minPrice`/`maxPrice` | — | два `input` |
| Наличие | `available`, `photo` | — | 2 чекбокса (Доступно к заказу / Только с фото) |
| **Характеристики** | `spec` | **курируемые пресеты** (`catalog-spec-filters.ts`) | чекбоксы по группам |
| **Параметры товаров** | `attr` | **структурные фасеты** (`catalog-attribute-filters.ts` + registry) | чекбоксы по группам |
| Диапазоны | `attrMin.*`/`attrMax.*` | числовые атрибуты (range) | парные `input` |

**Два параллельных механизма «характеристик» (ключевая особенность):**
- **`spec` — курируемые пресеты** (`catalog-spec-filters.ts`): ~33 готовых тематических переключателя («No Frost», «Двухкамерные», «4K/UHD», «Smart TV», «От 55″», «SSD», «RAM от 16 ГБ», «Узкие», «Инверторные»…), сгруппированы (`groupLabel`: Климат/Холодильники/Телевизоры/Компьютеры/Садовая техника/Стиральные машины). Показ — по `categoryHints` (вхождение подстроки в название категории). Where = OR из `attributeFilters` (по `Product.attributes`) И/ИЛИ `searchTerms` (поиск по `name`/`supplierName`).
- **`attr` — структурные фасеты** (`catalog-attribute-filters.ts` + `catalog-attribute-registry.ts`): ~58 определений параметров, 16 «семейств» (`families`). `getCatalogAttributeFamilyForCategory()` мапит категорию по regex названия/slug на семейство; `getCatalogAttributeKeysForCategory()` отдаёт релевантные ключи (universal + семейство). Where = AND по `attributes.some({key, normalizedValue})`; диапазоны — по `numericValue gte/lte`.

**Данные (`Product.attributes` — таблица `ProductAttribute`):** наполняется парсером из названий: `product-attributes.ts` (`extractProductNameAttributes`) → `product-attribute-backfill.ts` → `scripts/sync-product-attributes.ts`. Известный долг (БД): `name` часто `null` (используется `supplierName`), у многих товаров атрибутов нет, парсер покрывает ограниченный набор типов (стиралки/холодильники/посудомойки/микроволновки/духовки/панели — Iter 35–36).

**CSS (`glass-template.css`):**
- `.cat-layout{grid-template-columns:280px 1fr}` — левая колонка **жёстко 280px** (desktop). На `≤900px` → `1fr` (одна колонка; фильтры уходят в мобильный шит).
- `.f-row{display:flex;gap:10px;font-size:14px}`, `.f-row .box` (чекбокс), `.f-row .cnt{margin-left:auto}` (счётчик).
- `SearchableCheckboxList`: значение в `<span style="overflow:hidden;text-overflow:ellipsis">` → **жёсткая обрезка ellipsis**; контейнер списка `maxHeight:220; overflow:auto`; поле поиска появляется при `options.length>6`.

## 3. Аудит: найденные проблемы

### Ось A — Дизайн / вёрстка (главная жалоба владельца: «не вмещаются, обрезаются, не увеличиваются»)
- **A1 (P0).** Значения фильтров обрезаются `ellipsis` в колонке 280px. Длинные бренды и enum-значения («Расположение морозильника», длинные модели брендов) рубятся на полуслове, полный текст недоступен (нет переноса, нет tooltip). → `SearchableCheckboxList` (span ellipsis) + `.cat-layout` 280px.
- **A2 (P0).** Счётчик `.cnt` (`margin-left:auto`) отъедает ширину у и без того узкого значения → обрезка усиливается на популярных фасетах с 4–5-значными числами.
- **A3 (P1).** Колонка фиксирована 280px и «не увеличивается» — нет адаптации под длину контента/ширину экрана (на широких мониторах место есть, но колонка не растёт).
- **A4 (P1).** Панель — длинная «простыня» секций без сворачивания (аккордеонов): бренд + цена + наличие + характеристики + параметры + диапазоны идут подряд; на категории с многими фасетами скролл огромный, ориентироваться тяжело.
- **A5 (P1, мобайл).** Мобильный шит частично доведён (Iter 32: чекбоксы вправо/крупнее/разделители/живая индикация), но переносы длинных значений и аккордеоны не сделаны; нужно довести до единого вида с desktop.
- **A6 (P2).** Нет блока «активные фильтры» (чипы с ×) над листингом — выбранное видно только внутри панели; на мобиле после закрытия шита непонятно, что применено (есть только бейдж «Фильтры N»).

### Ось B — Логика подбора / маркетинг
- **B1 (P0).** **Дублирование двух механизмов.** «Характеристики» (`spec`-пресеты) и «Параметры товаров» (`attr`-фасеты) — две разные секции, частично об одном и том же: `fridge_no_frost`, `smart_tv`, `screen_diagonal` представлены и пресетом, и структурным фасетом. Покупатель видит «No Frost» дважды в разных местах — путаница, ощущение хаоса.
- **B2 (P1).** **Покрытие семейств неполное.** `getCatalogAttributeFamilyForCategory` опирается на regex по названию категории. Нужно проверить, что ВСЕ приоритетные топ-категории попадают в правильное семейство (встраиваемая техника, посудомойки, варочные панели, духовки, вытяжки, микроволновки, кофемашины — часть может не матчиться и проваливаться в `universal` → нерелевантные/пустые фильтры). Семейства `dishes/appliance` пересекаются — уточнить.
- **B3 (P1).** **Мусорные/нерелевантные значения** в фасетах из-за парсинга названий (db-data-trap): одиночные кривые атрибуты, значения-выбросы. Нужны пороги (мин. число товаров на значение) и чистка.
- **B4 (P1).** **Порядок и приоритет.** Внутри категории параметры должны идти по важности для покупателя (для холодильника: объём → No Frost → класс → размеры → бренд), а не в произвольном порядке `keyRank`. Маркетинговый порядок по семействам.
- **B5 (P2).** **`spec`-пресеты завязаны на поиск по названию** (`searchTerms` по `name`/`supplierName`) — ненадёжно (порядок слов, опечатки поставщика, `name=null`). Где есть структурный атрибут — предпочитать его.
- **B6 (P2).** Нет «быстрых подборок» в едином виде — пресеты есть, но не вынесены как заметные 1-клик чипы (маркетингово ценный паттерн).

### Ось C — Данные / парсер
- **C1 (P1).** Парсер `extractProductNameAttributes` покрывает ограниченный набор типов. Для топ-категорий нужно расширить: вытаскивать объём/класс/No Frost/размеры (холодильники), загрузку/отжим/узкие (стиралки), диагональ/разрешение/Smart (ТВ), и т.д. — по согласованному списку семейств.
- **C2 (P1).** После расширения парсера нужно **прогнать backfill** (`scripts/sync-product-attributes.ts`) на проде, чтобы наполнить `ProductAttribute` — иначе новые правила не дадут фасетов.
- **C3 (P2).** Нужны guard-тесты против повторения старых ловушек (smart_tv у не-ТВ, «смартфон»≠SmartTV — Iter 36) и против выбросов.

### Ось D — Функционал
- **D1.** Проверить вживую: применение (desktop «Применить» vs mobile sticky «Показать»), сброс (`Сбросить` → `basePath`), сохранение `q`/`sort` в hidden-инпутах, накопление нескольких значений (`getAll`), счётчик активных (`countActiveFilters`).
- **D2.** Контекстные счётчики фасетов: показывать, сколько товаров даст значение С УЧЁТОМ уже выбранных фильтров (сейчас фасеты считаются — проверить корректность пересчёта при активных фильтрах; `buildCatalogAttributeFacetProductWhere` это умеет — верифицировать).
- **D3.** Фасеты с `count=0` не показывать (кроме уже выбранных) — проверить, что соблюдается во всех ветках.
- **D4.** Производительность: пересчёт фасетов на больших категориях (десятки тысяч товаров) не должен ронять cold-start; учесть кэш (`STOREFRONT_CACHE_SECONDS`) и пул Prisma (известный P2024).

## 4. Целевое решение

### 4.1 Дизайн панели фильтров

**Рекомендуемый вариант (Вариант 1 — «аккуратный сайдбар с аккордеонами»):**
- **Колонка:** `.cat-layout` — сделать левую колонку гибкой: `clamp(280px, 24vw, 340px)` (растёт на широких экранах, не уже 280px). `box-sizing:border-box`.
- **Значения:** в `SearchableCheckboxList` убрать жёсткий `ellipsis` — перенос в 2 строки (`-webkit-line-clamp:2`, `word-break`), полный текст доступен (`title`-tooltip на desktop). Чекбокс `.box` и счётчик `.cnt` — `flex:0 0 auto`, значение `flex:1; min-width:0`.
- **Счётчик:** не отъедает ширину — компактный, переносится под значение при нехватке места (или прячется при очень узком).
- **Аккордеоны:** каждую группу (Бренд/Цена/Наличие/Параметры/Диапазоны) — в сворачиваемую секцию (`<details>`-подобный паттерн, client-island, доступный). По умолчанию открыты: Цена, Наличие, топ-2 параметра категории; остальные свёрнуты. Снимает «простыню» (A4).
- **«Показать ещё (N)»:** для списков значений > 8 — показывать первые 8 + раскрытие (вместо только внутреннего скролла 220px).
- **Активные чипы:** над листингом — ряд чипов выбранных фильтров с «×» (каждый снимает свой параметр) + «Сбросить всё». Решает A6.
- **Mobile (`mobile-filter-sheet`):** довести до того же языка — аккордеоны, переносы значений, чекбоксы справа/крупные (Iter 32 уже), активные чипы, sticky-футер «Показать N товаров». Полноэкранный шит.

*Альтернативы (отвергнуты):* Вариант 2 — горизонтальная панель быстрых фильтров над листингом + минимум в сайдбаре (больше переделок, риск для desktop). Вариант 3 — только локальный фикс обрезки без аккордеонов (дёшево, но «простыня» и захламление остаются — не закрывает жалобу полностью).

### 4.2 Логика: единая модель фильтров по категории

**Рекомендуемый вариант (Вариант A — «быстрые подборки + структурные фасеты, без дублей»):**
- **Вверху панели — «Быстрые подборки»** (бывшие `spec`-пресеты) как заметные 1-клик чипы/переключатели, маркетингово ценные («No Frost», «4K», «Узкие», «Инверторные»…). Это шорткаты.
- **Ниже — структурные параметры** (`attr`-фасеты) по семейству категории, в маркетинговом порядке важности.
- **Устранить дубли (B1):** если критерий есть и пресетом, и структурным фасетом — он показывается в ОДНОМ месте. Правило: булевы/популярные → в «Быстрые подборки»; перечисляемые/числовые → в структурные. Пресет, дублирующий структурный фасет, либо убирается, либо явно помечается как шорткат той же сущности.
- **Релевантность (B2):** аудит и доработка `getCatalogAttributeFamilyForCategory` + `categoryHints` — гарантировать, что приоритетные топ-категории матчатся в верное семейство; добавить недостающие (встраиваемая/посудомойки/духовки/панели/вытяжки/микроволновки/кофемашины).
- **Пороги и чистка (B3):** не показывать значение фасета с числом товаров ниже порога (напр. < 3) — кроме уже выбранного; глобальный «чёрный список» мусорных значений.
- **Порядок (B4):** задать маркетинговый порядок параметров по семействам (важное — вверху).

*Альтернативы:* Вариант B — полностью слить spec+attr в один список (теряется ценность курируемых пресетов, сложнее). Вариант C — оставить две секции, лишь переименовать (не убирает дубли — отвергнут).

### 4.3 Данные: расширение парсера атрибутов
- Расширить `extractProductNameAttributes` (`product-attributes.ts`) по приоритетным семействам (список — §5), с guard-тестами (C3).
- Прогнать backfill на проде (`scripts/sync-product-attributes.ts`) после деплоя парсера (C2) — отдельный операционный шаг (как warmer-скрипты), с логом и идемпотентностью.
- Не ломать существующие парсеры; только добавлять паттерны.

### 4.4 Функционал
- Верифицировать D1–D4 вживую (desktop + mobile) и тестами. Контекстные счётчики, скрытие `count=0`, корректный сброс, сохранение `q`/`sort`.

## 5. Охват: приоритетные семейства/категории (первая волна)

Образцово проработать (дизайн + релевантность + парсер + проверка):
1. **Холодильники / морозильники** (`refrigeration`)
2. **Стиральные / сушильные машины** (`laundry`)
3. **Телевизоры** (`tv`)
4. **Встраиваемая и кухонная техника** (`appliance`/`dishes`: посудомойки, духовые шкафы, варочные панели, вытяжки, микроволновки, кофемашины) — проверить покрытие семейств, возможно ввести/уточнить семейство.
5. **Климатическая техника** (`climate`: кондиционеры/сплит, осушители, увлажнители)
6. **Пылесосы** (`cleaning`)

Вторая волна (тиражирование по образцу): компьютеры, садовая техника, электрика, остальное. **Непрофильные категории** (одежда/стройка/сад-расходники) — фильтры остаются базовыми (бренд/цена/наличие), без насилия над данными.

## 6. Нефункциональные требования
- **Производительность:** пересчёт фасетов на больших категориях не должен увеличивать cold-start сверх текущего; использовать существующий кэш и беречь пул Prisma (P2024). Профилировать топ-категории.
- **Доступность:** аккордеоны/чипы — клавиатура + `aria` (детали/`aria-expanded`, `aria-pressed`).
- **RSC/Next 16:** не передавать функции server→client; client-острова (аккордеон, чипы) — отдельными компонентами; `setState` в effect только через setTimeout/then (lint-правило).
- **Тесты:** обновить/добавить юнит-тесты для registry-маппинга категорий, дедупликации spec/attr, порогов, парсера (guard-кейсы). Сохранить зелёную базу.

## 8. Критерии приёмки и план верификации
1. **Код-гейты:** `npm run lint` чисто, `npm run test` зелёный (база + новые), `npm run build` зелёный.
2. **Юнит:** маппинг категория→семейство для всех приоритетных категорий; дедуп spec/attr; пороги; парсер guard-кейсы.
3. **Живой desktop:** в 3–4 топ-категориях — фильтры релевантны, ничего не обрезается/не вылезает, аккордеоны и чипы работают, применение/сброс корректны. (Скрин/проверка — способ уточнить, т.к. Chrome-MCP виснет на каталоге; вариант — узкое окно/реальный desktop владельца.)
4. **Живой mobile (ADB):** шит в тех же категориях — переносы, чекбоксы, аккордеоны, чипы, «Показать N», применение.
5. **Данные:** после backfill — заметный рост доли товаров с атрибутами в топ-категориях (замер до/после по нескольким категориям).
6. **Прод-смоук:** ключевые роуты 200; несколько категорий с разными комбинациями фильтров.

## 9. Риски и зависимости
- **Данные кривые** (db-data-traps) — парсер не вытащит всё; честно показываем только наполненные фасеты.
- **Backfill на проде** — операционный шаг вне обычного deploy (как warmer); нужен прогон скрипта + лог. Согласовать с владельцем.
- **Производительность фасетов** на 54k — профилировать, не уронить cold-start.
- **Chrome-MCP/headless** не даёт desktop-визуал из окружения — desktop-приёмка через узкое окно/скрины владельца.
- **Деплой/backfill на прод — только с явного ОК владельца** (его правило).
