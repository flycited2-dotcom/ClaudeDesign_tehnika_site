## 3. Что было доделано перед тестами (доработка по отчёту 2026-06-07)

- **Мобильная оболочка**: рабочее бургер-меню (off-canvas сайдбар + скрим), убран
  горизонтальный overflow, адаптивный topbar/шапки/таблицы.
- **Logout**: «Выйти» в профиле очищает роль и ведёт на login; «Профиль» ведёт в карточку
  сотрудника, «Настройки» — в настройки.
- **Создание лида**: новая модалка `create-lead` (раньше — `modal: null`, B0-4),
  плюс модалка `create-tender`.
- **Кнопки «+» на всех списках** открывают соответствующие модалки; CTA на
  empty-state открывает модалку напрямую.
- **Клик по строке** в таблицах сделок/КП/тендеров/клиентов открывает запись;
  иконка «глаз» — ссылка.
- **Календари** задач и тендеров листаются стрелками.
- **favicon.ico** добавлен и отдаётся сервером.
- **Реальные точки входа лидов** (по списку владельца): `splihub.ru`, `splihome.ru`,
  `climat-simf.ru`, `Приложение SplitHub` (splithub.apk), `Авито`,
  `Парсинг тендеров` (входящий файл от парсера), `Звонок входящий` (ручной) —
  в mock-данных, списке лидов, настройках источников и «Сайты и токены».
- **Интеграции**: Google Диск, Почта Google (Gmail), вебмейл сайта (SMTP/IMAP),
  Парсинг отелей (файл рассылки, база HoReCa), База монтажников (парсинг подрядчиков),
  Telegram-бот; 1С и MAX — помечены как этап 2.

## 4. Дефекты, найденные тестами и исправленные в этой сессии

1. **Горизонтальный overflow на дашборде собственника @390** — три причины:
   таблица сотрудников растягивала карточку (нет scroll-контейнера),
   `position: sticky` у заголовков таблиц расширял документ на мобильных,
   `#problem-grid` оставался двухколоночным на узких экранах.
   Исправлено: универсальное правило «контейнер таблицы скроллится» (`:has`),
   отключение sticky th на ≤900px, одна колонка problem-grid на ≤640px.
2. **Горизонтальный overflow на дашборде менеджера @390** — детям грида
   `.two-col-row` не давали сжиматься (`min-width: auto`). Исправлено
   `min-width: 0` при ≤1024px (обоим дашбордам).

Ложные срабатывания тестов (исправлены в самом тесте, не в продукте):
- проверка очистки роли после logout — тест-харнесс сам пересеивал `localStorage`;
- скелетоны живут 600 мс и сменяются данными «по дизайну» — тест ловил их слишком поздно.

## 5. Как повторить тесты

```bash
node serve.mjs          # терминал 1 (или уже запущен)
node qa-deep-test.mjs   # терминал 2 — печатает PASS/FAIL и пишет JSON
```

## 6. Известные ограничения (этап 2 — backend, вне рамок прототипа)

Без изменений с отчёта 2026-06-07 — прототип статический, поэтому:

- авторизация фиктивная (любые данные пускают), ролей на сервере нет — роль в localStorage;
- «Сохранить»/«Создать» в модалках не пишут данные — записи не появляются;
- webhook-endpoint'ы `/api/webhooks/*` — только наименования в UI;
- фильтры на списках, CRUD в настройках, отправка сообщений/КП, закрытие сделки,
  действия тендера — декоративные;
- отчёты строятся по mock-данным.

Эти пункты закрываются только реализацией API/БД по `crm_project_docs/06_API_SPEC.md`
(стек Next.js/NestJS/Postgres — после утверждения визуала).
