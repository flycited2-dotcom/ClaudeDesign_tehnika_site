# Техническое задание на разработку CRM-системы

## 1. Назначение системы

CRM-система разрабатывается как внутренняя система управления торговой компанией, занимающейся продажей климатической техники, бытовой техники, кондиционеров, B2B-поставками, работой с монтажниками, розничными клиентами, государственными объектами и тендерами.

Система предназначена только для внутреннего использования компании.

CRM должна обеспечить:

- единый учет клиентов;
- контроль входящих заявок;
- ведение сделок;
- постановку и контроль задач;
- формирование коммерческих предложений;
- отправку КП по email и Telegram;
- контроль рабочего времени сотрудников;
- учет коммуникаций;
- подключение сайтов компании;
- подготовку к интеграции с 1С;
- тендерный контур;
- аналитику для собственника.

## 2. Разделение ответственности CRM и 1С

CRM не должна дублировать полноценный складской и бухгалтерский учет.

### 1С остается ответственной за:

- складские остатки;
- резервы;
- счета;
- реализации;
- оплаты;
- бухгалтерию;
- движение товара;
- документы;
- закупки;
- управленческий и регламентированный учет.

### CRM отвечает за:

- клиентов;
- лиды;
- сделки;
- задачи;
- КП;
- коммуникации;
- контроль сотрудников;
- заявки с сайтов;
- уведомления;
- воронки продаж;
- тендеры;
- управленческую аналитику.

## 3. Пользователи системы

На первом этапе предполагается 5–6 активных пользователей:

- собственник;
- руководитель;
- бухгалтер;
- менеджер 1;
- менеджер 2;
- администратор.

Система должна проектироваться с запасом для расширения до 20–50 пользователей без изменения архитектуры.

## 4. Роли

### 4.1. Собственник

Имеет полный доступ ко всем разделам, данным, отчетам, журналам, настройкам и действиям пользователей.

### 4.2. Руководитель

Контролирует менеджеров, сделки, задачи, КП, просрочки, воронки, входящие заявки и отчеты отдела.

### 4.3. Менеджер

Работает со своими клиентами, лидами, сделками, задачами, КП и коммуникациями.

### 4.4. Бухгалтер

Работает с реквизитами, КП, финансовой информацией, счетами, оплатами и интеграцией с 1С после второго этапа.

### 4.5. Администратор

Настраивает пользователей, роли, справочники, шаблоны, интеграции и технические параметры.

## 5. Основные модули

### 5.1. Авторизация

Функции:

- вход по логину и паролю;
- безопасное хранение паролей;
- JWT/refresh token;
- роли и права;
- журнал входов;
- фиксация времени входа;
- фиксация времени выхода;
- блокировка пользователя;
- смена пароля.

### 5.2. Рабочий стол

Для каждого пользователя рабочий стол строится с учетом роли.

Менеджер видит:

- задачи на сегодня;
- просроченные задачи;
- свои активные сделки;
- новые назначенные лиды;
- КП, требующие контроля;
- последние комментарии;
- быстрые действия.

Собственник видит:

- количество новых заявок;
- необработанные заявки;
- активные сделки;
- просроченные задачи;
- отправленные КП;
- сотрудников онлайн;
- сотрудников, не вошедших в систему;
- сделки без движения;
- тендерные дедлайны;
- KPI менеджеров.

### 5.3. Клиенты

Карточка клиента должна содержать:

- тип клиента;
- ФИО или название компании;
- ИНН;
- КПП;
- ОГРН;
- адрес;
- город;
- телефон;
- email;
- Telegram;
- MAX;
- источник;
- ответственный менеджер;
- статус клиента;
- комментарии;
- сделки;
- КП;
- задачи;
- файлы;
- история действий.

Типы клиентов:

- монтажник;
- розничный клиент;
- юридическое лицо;
- государственный заказчик;
- поставщик;
- партнер;
- прочий.

Статусы клиентов:

- новый;
- активный;
- постоянный;
- VIP;
- проблемный;
- неактивный;
- поставщик;
- госзаказчик.

### 5.4. Лиды

Лид — первичная заявка из любого источника.

Источники:

- SplitHub.ru;
- розничный сайт климатической техники;
- сайт бытовой техники;
- Telegram;
- email;
- ручное добавление;
- Excel;
- тендерная площадка;
- прочее.

Карточка лида:

- источник;
- сайт;
- страница;
- UTM-метки;
- имя;
- телефон;
- email;
- Telegram;
- сообщение;
- интересующий товар;
- город;
- IP;
- дата поступления;
- ответственный;
- статус;
- комментарии;
- история обработки.

Статусы:

- новый;
- в работе;
- квалифицирован;
- создана сделка;
- отказ;
- дубль;
- некачественный лид.

Обязательное правило: новый лид не должен находиться без ответственного более 15 минут. При нарушении отправляется уведомление руководителю и собственнику.

### 5.5. Сделки

Сделка является основным рабочим объектом CRM.

Поля сделки:

- номер;
- клиент;
- направление;
- ответственный;
- сумма;
- маржа;
- статус;
- этап воронки;
- источник;
- товары;
- КП;
- задачи;
- файлы;
- комментарии;
- дата создания;
- плановая дата закрытия;
- причина отказа.

Направления:

- B2B / монтажники;
- розница / климатическая техника;
- розница / бытовая техника;
- тендеры;
- госзаказы;
- сервисные заявки;
- прочее.

### 5.6. Воронки продаж

#### B2B

1. Новый лид.
2. Связались.
3. Подбор товара.
4. КП отправлено.
5. Согласование.
6. Резерв / счет.
7. Оплата.
8. Отгрузка.
9. Закрыто успешно.
10. Отказ.

#### Розница

1. Заявка с сайта.
2. Консультация.
3. Подбор товара.
4. КП / предложение.
5. Согласование.
6. Оплата.
7. Доставка.
8. Закрыто успешно.
9. Отказ.

#### Тендеры

1. Найден тендер.
2. Анализ ТЗ.
3. Проверка товара.
4. Расчет цены.
5. Подготовка документов.
6. Подача заявки.
7. Ожидание итогов.
8. Победа.
9. Контракт.
10. Поставка.
11. Закрытие документов.
12. Проигрыш / отказ.

### 5.7. Задачи

Поля задачи:

- название;
- описание;
- постановщик;
- исполнитель;
- дедлайн;
- приоритет;
- статус;
- связанный клиент;
- связанная сделка;
- связанный тендер;
- файлы;
- комментарии;
- история изменений.

Статусы:

- новая;
- в работе;
- ожидает ответа;
- на проверке;
- выполнена;
- просрочена;
- отменена.

Приоритеты:

- низкий;
- обычный;
- высокий;
- срочный;
- критический.

Автоматические задачи:

- обработать новый лид;
- связаться после отправки КП;
- проверить сделку без движения;
- проверить тендерный срок;
- связаться с клиентом без активности.

### 5.8. Коммерческие предложения

CRM должна формировать КП по шаблонам компании.

Функции:

- выбор клиента;
- выбор компании-отправителя;
- выбор шаблона;
- добавление товаров;
- количество;
- цена;
- скидка;
- НДС / без НДС;
- доставка;
- срок действия КП;
- комментарий;
- генерация PDF;
- отправка по email;
- отправка в Telegram;
- сохранение КП в сделке;
- история версий.

Статусы КП:

- черновик;
- создано;
- отправлено;
- согласовано;
- отклонено;
- заменено новой версией.

### 5.9. Email

На первом этапе требуется исходящая почта:

- отправка КП;
- отправка писем клиентам;
- шаблоны писем;
- вложения;
- подпись;
- сохранение факта отправки в клиенте и сделке.

Входящую почту подключить на последующих этапах.

### 5.10. Telegram

Telegram является ключевым каналом уведомлений.

Функции:

- уведомления сотрудникам;
- уведомления руководителю;
- уведомления о новых заявках;
- уведомления о задачах;
- уведомления о просрочках;
- отправка КП клиенту;
- привязка Telegram клиента к карточке;
- история сообщений.

### 5.11. MAX

На первом этапе реализация MAX не требуется, но архитектура должна предусматривать адаптеры мессенджеров:

- TelegramAdapter;
- EmailAdapter;
- MaxAdapter;
- WhatsAppAdapter.

### 5.12. Сайты

CRM должна принимать заявки с сайтов:

- SplitHub.ru;
- розничный сайт климатической техники;
- сайт бытовой техники;
- будущие лендинги.

Заявка с сайта должна автоматически создавать лид.

### 5.13. Тендеры

Карточка тендера:

- номер тендера;
- площадка;
- заказчик;
- НМЦК;
- дата публикации;
- дата окончания подачи;
- дата аукциона;
- ответственный;
- статус;
- товары;
- требования;
- документы;
- КП;
- расчет цены;
- маржа;
- результат;
- комментарии;
- задачи.

### 5.14. Интеграция с 1С

Интеграция реализуется на втором этапе.

CRM → 1С:

- новый клиент;
- заказ;
- резерв;
- запрос счета;
- комментарий к заказу;
- данные сделки.

1С → CRM:

- остатки;
- цены;
- статус резерва;
- номер счета;
- статус оплаты;
- статус отгрузки;
- задолженность;
- документы.

### 5.15. Аналитика

Для собственника:

- лиды;
- сделки;
- сумма сделок;
- конверсия;
- отправленные КП;
- просроченные задачи;
- эффективность менеджеров;
- активность сотрудников;
- источники заявок;
- тендерная статистика;
- сделки без движения;
- клиенты без контакта;
- заявки без ответа.

## 6. MVP

В первую версию входит:

1. Авторизация.
2. Роли.
3. Рабочий стол собственника.
4. Рабочий стол менеджера.
5. Клиенты.
6. Лиды.
7. Сделки.
8. Задачи.
9. КП.
10. Учет входа/выхода сотрудников.
11. Telegram-уведомления.
12. Email-отправка КП.
13. Базовые отчеты.
14. Журнал действий.
15. Настройки пользователей.

В MVP не входит:

- полноценная интеграция с 1С;
- MAX;
- WhatsApp;
- телефония;
- сложный склад;
- GPS;
- скриншоты;
- мобильное приложение;
- AI-автоматизация.

## 7. Критерии готовности MVP

MVP считается готовым, если:

- собственник видит всех сотрудников;
- сотрудники входят в CRM;
- фиксируется время входа и выхода;
- можно создать клиента;
- можно создать лид;
- можно создать сделку;
- можно поставить задачу;
- задача имеет дедлайн и статус;
- можно создать КП;
- КП сохраняется в сделке;
- КП можно отправить по email;
- уведомления приходят в Telegram;
- собственник видит просрочки;
- есть базовая аналитика;
- система стабильно работает для 5–6 пользователей.
